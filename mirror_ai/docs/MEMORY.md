## About this file

MEMORY.md is the human-readable snapshot of the current roster state. It is regenerated from Redis on every roster write. The authoritative data lives in Redis (`mirror:roster`). This file is a convenience view for reading in a text editor or reviewing in version control.

The roster holds up to 10 active members. Each member has:
- A **weight** between 0.5 and 1.6 that reflects how much their trades influence signal scores. It starts at a value the AI assigns during bootstrapping (typically 0.8–1.2) and drifts up or down based on 30-day trade outcomes.
- A **performance_since_added** value tracking cumulative P&L % from all mirrored trades attributed to this person.
- An **added_date** and **last_reviewed** timestamp for audit purposes.

## Manual edits

If you need to manually adjust the roster outside of the weekly review cycle:

1. Use the dashboard ROSTER tab → "Add a new person to the roster" or "Remove" buttons.
2. Changes take effect immediately and are written to Redis.
3. This file (MEMORY.md) is regenerated within seconds of any roster change.
4. All changes are logged to CHANGELOG.md with a timestamp and reason.

Do not directly edit the Redis keys. Always use the dashboard or Telegram commands to ensure the changelog is updated properly.
